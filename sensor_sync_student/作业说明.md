# 作业说明

## 1. 队列已满或为空时，线程如何进入等待状态

消费者在 `pop` 中使用 `std::condition_variable::wait`，等待条件是队列非空或队列已关闭。等待期间不占用互斥锁，生产者入队后通过条件变量唤醒消费者，避免忙等和定时轮询。

## 2. 如何判断最后一个生产者已经结束

主线程分别 `join` 相机和 IMU 两个生产者线程；只有两个 `join` 都返回后，才调用队列的 `close()`。因此关闭动作明确发生在最后一个生产者结束之后。

## 3. 为什么关闭队列后仍允许消费者读取剩余数据

`close()` 只禁止新数据进入，并唤醒所有等待线程；`pop` 在关闭状态下仍会先检查并返回队列中已有的数据，直到队列为空才返回 `false`。这样可以保证已经生产的数据不会丢失。

## 4. 时间戳匹配算法的具体流程和复杂度

先分别按时间戳、序号排序。使用只向前移动的 IMU 下标扫描相机数组，将下标移动到第一个不早于当前相机时间戳的位置，只比较该位置和前一个位置两个候选，并按绝对时间差、较早时间戳、较小序号依次决胜。
排序复杂度为 `O(C log C + I log I)`，匹配扫描复杂度为 `O(C + I)`，总复杂度为 `O(C log C + I log I + C + I)`，额外空间为 `O(C + I)`。

## 5. 如何处理时间差相同、时间戳相同的边界情况

绝对时间差相同时选择时间戳更早的 IMU；如果时间戳仍相同，则选择序号更小的 IMU。差值小于等于 `max_delta_us` 才算匹配，等于边界值也算匹配。一个 IMU 包可以被多个相机包复用。

## 6. 如果某个生产者读取文件失败时如何保证其他线程退出

生产者在线程函数内部捕获异常，保存第一个异常并关闭队列。关闭会唤醒阻塞的 `push` 和 `pop`，另一个生产者和消费者能够正常结束；主线程 `join` 所有线程后重新抛出异常并以非零状态退出。
